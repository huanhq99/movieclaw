## movieclaw v0.15.0

这一版的主线是**刷流更懂让路**：刷流下载不再跟正常上传抢带宽，上行一受压就秒级退让；
同时补齐了刷流的数据记录，为后续策略调优打底。媒体库实时监控在网络挂载上可以关掉、
监听链路整体提速，移动端 PWA 手感与若干页面排版也做了一轮打磨。

### 新功能

- **刷流带宽哨兵（清道夫模式）**：刷流下载只吃剩余带宽——每 20 秒巡检下载器全局
  速度，上行一掉出健康区就立刻按种限速让路（只碰刷流任务，不影响你自己的下载）；
  后台还会慢慢学习本环境的安全下载包络，拥塞就收、健康就放，全程零配置。配套三条
  准入纪律：低分种子不收（评分 < 3）、同时在下不超过 3 个（高分种近似独享带宽、
  最早开始做种）、按实测速率预测免费窗口赶不上就提前放弃，不再白下一半
- **刷流可观测性**：台账新增入场快照（当时的做种/下载人数、评分、发布时间）与下载
  量差分，小时桶加下载增量和上/下行速度采样，新增每任务小时级快照表与新种蜂群演化
  采样表——哪类种子值得抢，以后有数可查
- **媒体库实时监控可按库关闭**：SMB/CIFS/NFS 网络挂载上 inotify 收不到远端变更，
  实时监控纯付成本。库编辑弹窗新增「实时监控目录变化」开关（默认开），关闭后该库
  不建监听，靠定期对账与手动扫描兜底，新文件不实时但不会缺失

### 改进

- **媒体库监听链路系统性提速**：监听触发的扫描只遍历变动子树，不再全库重扫；目录
  遍历改用 scandir 省掉大量 stat（网络挂载每次 stat 都是一轮往返）；盘点遍历放线程池，
  大库/慢盘不再冻住服务；库/规则编辑后差量增删监听，未变的根零成本；建监听全程后台
  执行，不再拖慢启动（此前网络挂载可触发启动超时）；扫描进行中收到的事件扫完补触发，
  不用再等 6 小时对账
- **PWA 手感贴近原生**：移动端装成 App 后，长按导航项、按钮、列表行不再拖出蓝色选区
  和系统拷贝菜单；真正值得复制的内容（输入框、正文、代码块、路径/哈希/代理地址等
  等宽机器数据、加载失败页报错）全部保持可选，局域网 HTTP 下「长按选中手动复制」
  这条兜底路仍然走得通
- **任务中心**：时间轴条目与分组标题左对齐，不再被空白的时刻列推开近 100px；刷流
  做种展开后改为固定列（站点 / 名称 / 上行速度 / 累计上传 / 体积），按上行速度倒序，
  「现在谁在出力」永远浮在最前；筛选标签改为 全部 / 进行中 / 需要处理 / 已结束，
  顺着任务生命周期读
- **站点设置（桌面端）**：分区加宽，展开详情的段标签抽成左侧固定列、统计改等宽列
  纵向成列，读起来像一张规格表；展开箭头加 hover 热区、展开中的行有底色、补齐键盘
  焦点环
- **影片详情页**：背景回到全局沉浸——进页面整站背景换成该片剧照（加载完才淡入、
  离开淡出），不再只铺页面顶部一块；「相似推荐」「系列电影」横滚行对齐正文栅格，
  不再左戳出一截

### 修复

- 修复两条数据库迁移撞号导致 alembic 报重复 revision、分叉双 head 的问题（迁移链
  已收回单头，两条迁移此前未在任何环境执行过，改号不影响已有数据）

### 升级说明

- 首次启动会执行数据库迁移：刷流台账/采样表加列与新表、下载器新增带宽包络列、
  媒体库新增实时监控开关列；全部为加列与新表，向前兼容，应用内更新前仍会自动备份
  数据库，跨版本回退请用该备份恢复
- 本版本未改变 Python/Node 运行时依赖、Docker 基础镜像或入口契约，runtime 版本保持
  7；现有 runtime 7 用户可直接使用应用内一键更新，无需重拉镜像
