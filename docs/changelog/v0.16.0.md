## movieclaw v0.16.0

这一版主攻**播放与下载的性能根治**：NAS 上常驻 100% CPU、内存被页缓存吃光、并发下载跑不满带宽
三个症状追到了同一个根——客户端断开后服务端仍把整个媒体文件读到底，以及所有流量都要经
Node 反代一跳。修掉之后，同机实测取流/下载的 CPU 开销降到原来的约 1/5，容器内存从 7.6 GB
回到几百 MB。容器内也因此引入 nginx 前门，并把对外端口做成了可在应用内设置。

> **本版需要更新 Docker 镜像（runtime 7 → 8）**：容器内新增 nginx 前门进程、入口脚本的
> 进程模型与端口约定都变了，旧镜像无法通过应用内更新直接升到本版——请重新拉取
> `movieclaw/movieclaw:v0.16.0`（或 `latest`）后启动。镜像同时把内置 NER 模型升到 torrent-ner-v3。

### 新功能

- **对外端口可在应用内设置**：「设置 → 应用设置」新增对外端口区块（优先级：应用内设置 >
  `MOVIECLAW_WEB_PORT` 环境变量 > 默认 3000），改完全量重启生效。新端口绑不上（被占用等）
  会自动废弃并回落到上一个可用端口，不会把自己关在门外；8000 为后端保留不可选。
  host 网络/裸机部署不再需要改镜像就能换端口；桥接部署仍建议直接改 compose 的端口映射左侧
- **容器内 nginx 前门**：对外端口由 nginx 接住，`/api/v1` 与 Jellyfin 播放接口直达后端，
  页面与静态资源交给 Next。播放器取流、整文件下载不再经过 Node 反代，每 GB 流量省约
  10 个 CPU 秒；启动/重启期间由 nginx 代答「正在启动」占位页，端口全程不消失

### 改进

- **取流/下载断连即停读盘（CPU/内存根治）**：播放器每次 seek 留下的旧连接、下载器取消的
  请求，此前都会让服务端把几十 GB 的文件继续读完（Starlette 的断连检测在中间件下失效），
  表现为常驻高 CPU、页缓存吃满内存、真正的下载被挤占。现在断开后一个数据块内即停读；
  传输块从 64 KiB 提到 1 MiB；访问日志等全局中间件改为零拷贝的纯 ASGI 实现
- **整文件下载（`/Items/{id}/Download`）**：同样具备断连即停，并保留 Content-Length，
  下载器的进度显示与断点续传不受影响
- **qBittorrent 客户端连接复用**：按连接参数共享底层客户端（keep-alive + 已登录会话），
  任务中心 5 秒轮询不再每次重做 DNS/TCP/TLS/登录；DNS 偶发丢包时接口耗时从 5~10 秒回到
  0.4 秒以内
- **下载器设置**：改为单开手风琴，与站点设置页同款交互；**影片详情页**剧照渐变改挂到
  滚动容器，滚动时不再错位；**任务中心**排版收口

### 内置模型

- Docker 镜像内置的 NER 模型从 torrent-ner-v2 升到 **torrent-ner-v3**（单集文件名季集识别修复）；
  已通过应用内模型更新装过 v3 的实例不受影响，新装实例开箱即是 v3
